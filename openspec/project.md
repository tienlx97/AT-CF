## Purpose

ANH-TU-COFFEE is the website of Anh Tú Coffee, a take-away espresso-machine coffee
shop (100% pure coffee) at Đường A8, Bình Tân, TP. Hồ Chí Minh. Mornings it sells
at the counter (05:30–11:00), afternoons and evenings online through ShopeeFood
and GrabFood (11:00–20:00). Source brief: `ANH-TU-PROMP.md` (owner's prompt).

Audience: neighbours and commuters, mostly on phones over 4G. In a few seconds a
visitor must be able to (1) see whether the shop is open now or selling online,
(2) read the menu and prices, (3) call, message on Zalo or get directions.

The site is image- and video-heavy (the shop has many photos and clips) yet must
load fast on mobile. Vietnamese only in v1; data is structured so English can be
added later without rewriting.

## Tech stack

- Language/runtime: JavaScript (Node 22 LTS, pnpm 11)
- Framework: Next.js 16 (App Router), static export (`output: 'export'`) — ADR-0005
- Styling: Tailwind CSS v4 (CSS-first `@theme` tokens in `src/app/globals.css`) — ADR-0005
- Font: Montserrat via `next/font/google` (subsets `latin`, `vietnamese`)
- Icons: `lucide-react`
- Data: JSON files edited by the owner — `src/data/site.json`, `src/data/menu.json`,
  `src/data/media.json` (generated by `pnpm media`, captions kept). No backend.
- Media: `sharp` (images) and `ffmpeg` (video) in `scripts/process-media.mjs`
- Testing: Node's built-in test runner (`node --test`)

## Architecture

Feature-based — see `docs/architecture.md` for the full map:

```
src/features/<feature>/{types,config,api,hooks,components}
src/shared/{types,config,api,hooks,components}
src/data/*.json   (owner-edited content, read only through src/shared/config)
```

Layer order inside each tree: `types → config → api → hooks → components`.
Features are isolated and reachable from outside only via their `index.js`;
`src/shared/` cannot depend on a feature. Enforced by the structural test in
`./harness/verify.sh` (dependency-cruiser config: `harness/structure.rules.cjs`).

## Conventions (linted, not aspirational)

- Naming: kebab-case files, camelCase functions, PascalCase React components.
  `.jsx` for any file containing JSX, `.js` for logic without JSX
  (`react/jsx-filename-extension` in `eslint.config.mjs`).
- Module boundaries: features only via their `index.js`; no cross-feature imports.
- Errors: handled at boundaries (`src/app`, each tree's `api`/`hooks`); no empty catch.
- Colour: only the Tailwind tokens `brand` `#2F6F55`, `brand-ink` `#1F3D31`,
  `surface` `#FFFFFF`, `surface-alt` `#EEF0EC` (plus Tailwind neutrals/white/black
  with opacity). No hex literals in `src/**/*.{js,jsx}` — lint rule
  `no-restricted-syntax` (hex colour) in `eslint.config.mjs`. Hex values live only
  in `src/app/globals.css` `@theme`.
- Logo: the files `assets/logo/leaf-mark.svg` / `leaf-mark-white.svg`, copied
  unchanged to `public/brand/`; never redrawn, recoloured or re-proportioned.
- No emoji, no cartoon icons, no loud gradients. Labels in small uppercase with wide tracking.
- Every convention here must map to a lint/structural rule; one that cannot be
  checked mechanically goes to `harness/GOLDEN_RULES.md` with a plan to automate it.
